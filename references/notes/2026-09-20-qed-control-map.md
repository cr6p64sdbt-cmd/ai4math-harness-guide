# QED 固定源码控制流图：学习笔记

范围：只读 [官方仓库 `121900964e6572aaf094412d434b5ac2a792a65f`](https://github.com/proofQED/QED/tree/121900964e6572aaf094412d434b5ac2a792a65f)，重点为 `code/pipeline.py`、`code/decomposition_prover.py`，必要时核对 `run.sh`、`config.yaml`、`code/model_runner.py`。本笔记描述 **2026-08-16 源码快照的静态控制流**；没有安装、执行 QED，也没有取得早期 PDE 案例的完整逐轮日志，不能将本版本的分支或配置倒填到该案例。已有版本及案例界限见 [系统档案](../../systems/qed.md) 和 [来源收据](2026-09-20-qed-expansion.md)。

## 入口与调用链

`run.sh` 默认取 `problem/problem.tex`、`proof_output`、`config.yaml`，先做 smoke test、将全局 `human_help/*` 以不覆盖旧文件的方式复制进输出目录，再 `exec` [ `pipeline.py --input --output --config`](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/run.sh#L7-L36)。直接调用 `pipeline.py` 时，这两项 shell 准备步骤并不由 Python 入口执行。

1. [`main()`](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/pipeline.py#L663-L717) 读配置、只接受 `prover.mode=decomposition`、检查输入；仅首次复制题目到输出目录的 `problem.tex`，每次调用覆盖 `config_used.yaml`。`check_prerequisites()` 当前还硬查 `claude` 与 `python3` 命令，即使角色配置选别的 provider；这只是入口门槛，不代表每一角色都会调用 Claude（[80–96 行](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/pipeline.py#L80-L96)）。
2. Stage 0 [`run_literature_survey()`](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/pipeline.py#L552-L629) 生成 `related_info/difficulty_evaluation.md`；`easy` 路径期望直接有顶层 `proof.md`，其他分类期望 `related_info/related_work.md`。恢复时按文件非空判定是否跳过调查（[201–214 行](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/pipeline.py#L201-L214)）。`easy` 且 `proof.md` 非空便直接返回，跳过 Stage 1/2；此路径没有调用分解证明核验链（[785–803 行](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/pipeline.py#L785-L803)）。
3. 其余路径由 [`main()` 调用 `run_decomposition_prover()`](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/pipeline.py#L805-L829)，传入题目、相关文献文件、配置和输出目录。Stage 2 再由 `proof_summary` 角色写 `proof_effort_summary.md`；已有非空摘要就跳过（[840–898 行](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/pipeline.py#L840-L898)）。辅助角色与六个证明角色通过 [`run_model_for_agent()`](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/model_runner.py#L708-L751) 将角色配置覆盖到 provider 全局配置，再分派给 Claude、Codex 或 Gemini CLI；角色名并不保证底层模型不同。

## Stage 1：三层重试与核验

目录和计数有三层（[`DecompositionState`](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/decomposition_prover.py#L284-L327)）：`decomposition/attempt_N/` 是一条策略，`revision_M/` 是该策略的计划版本，`proof_K/` 是该计划下的完整证明候选。新 `REWRITE`、`REVISE_PLAN`、`REVISE_PROOF` 分别递增这三层；换上层时重置下层计数（[393–422 行](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/decomposition_prover.py#L393-L422)）。

每轮的实走调用链为 [`run_decomposer`](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/decomposition_prover.py#L757-L877) → [`run_single_prover`](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/decomposition_prover.py#L880-L978) → [`run_structural_verification`](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/decomposition_prover.py#L1104-L1176) → `run_verdict(STRUCTURAL)`；仅 verdict 返回 `DONE` 才运行 [`run_detailed_verification`](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/decomposition_prover.py#L1179-L1246) → `run_verdict(FINAL)`。`run_verdict()` 另调模型读报告，返回文本中**含** `DONE` 即映射为 `DONE`，否则 `CONTINUE`（[1249–1322 行](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/decomposition_prover.py#L1249-L1322)）；它不是从证明步骤作形式判定。源码另有 `run_proof_verification()` 包装函数，但主循环没有调用它（[1325–1343 行](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/decomposition_prover.py#L1325-L1343)）。

结构 verdict 或最终 verdict 为 `CONTINUE` 时，才把失败报告交给 [`run_regulator()`](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/decomposition_prover.py#L981-L1097)。`REVISE_PROOF` 留在当前计划写下一份证明；`REVISE_PLAN` 新建 revision，再以先前证明、核验反馈和 regulator 建议修计划；`REWRITE` 新建 attempt，并以计划历史避免重复路线（[1751–1800 行](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/decomposition_prover.py#L1751-L1800)、[1844–1882 行](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/decomposition_prover.py#L1844-L1882)）。无法解析决策时默认 `REVISE_PROOF`（[261–277 行](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/decomposition_prover.py#L261-L277)）。

主循环的硬边界是 `attempt <= max_decompositions` 和每个 revision 内 `proof <= max_proof_attempts`。proof 次数耗尽时自动升到 plan revision；revision 用尽则换策略，即使此前 regulator 只要求重写证明。若 regulator 指向 `REVISE_PLAN` 但 revision 已超限，也改为 `REWRITE`；最终耗尽后让 regulator 以 `FINAL` 模式写 `decomposition/failure_analysis.md` 并把状态写为 `FAILED`（[1884–1980 行](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/decomposition_prover.py#L1884-L1980)）。固定 [`config.yaml`](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/config.yaml#L94-L122) 的 8/4/4 是该快照示例值；代码默认值为 3/2/3（[34–38 行](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/decomposition_prover.py#L34-L38)），具体运行须看当次配置。

## 磁盘状态与中断恢复

一份 revision 有 `decomposition.yaml` 和 `decomposer_response.md`；一份 proof 有 `proof.md`、`prover_response.md`、`structural_verification.md`、视阶段而有 `detailed_verification.md`、`regulator_decision.md` 与错误文件。模型没有按要求写目标文件时，若返回文本可用，decomposer/prover/verifier/regulator 各有相应的回填逻辑；`decomposition.yaml` 无法解析则抛错（[857–877 行](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/decomposition_prover.py#L857-L877)、[966–978 行](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/decomposition_prover.py#L966-L978)）。`decomposition/plan_history.md` 的预设是由 regulator 追加、供 decomposer 读取；脚本负责创建初始说明及传入路径，追加内容由模型按 prompt 执行，不能单凭文件存在推断每次失败都已准确记录（[329–358 行](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/decomposition_prover.py#L329-L358)、[1010–1045 行](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/decomposition_prover.py#L1010-L1045)）。

`decomposition/STATUS.md` 是状态显示，`log.txt` 是追加时间线；logger 构造时会先把 `STATUS.md` 写成 `STARTING`，后续更新函数也不真正解析既有字段，因此**恢复依据是目录和工件扫描，不是状态表**（[127–218 行](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/decomposition_prover.py#L127-L218)）。顶层 `AUTO_RUN_STATUS.md`、`.history`、`AUTO_RUN_LOG.txt` 是另一套 pipeline 日志；顶层 `proof.md` 在每次候选保存时被覆盖（[221–267 行](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/pipeline.py#L221-L267)、[380–386 行](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/decomposition_prover.py#L380-L386)）。

[`detect_decomposition_resume()`](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/decomposition_prover.py#L521-L682) 扫最大编号的 attempt/revision/proof：按工件有无选择 `decompose`、`decompose_revise`、`prove`、`verify_structural`、`verify_detailed`、`regulator`、`done`；已存结构报告的 `OVERALL VERDICT: PASS` 会跳详细核验，已存详细报告有这段字符串会判 `done`。主入口据扫描结果恢复计数和上一 revision 的反馈，再进入主循环（[1448–1634 行](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/decomposition_prover.py#L1448-L1634)）。这里恢复扫描依据**报告字符串**，正常运行接受依据却是额外模型的 `DONE`；两者并非同一判据。若失败报告后已有 `regulator_decision.md`，扫描器直接将 proof 编号加一并选择 `prove`，没有解析决策属于 `REVISE_PLAN` 还是 `REWRITE`（[644–673 行](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/decomposition_prover.py#L644-L673)）。所以只能说它有文件级断点恢复机制，不能声称任意中断点均语义等价地续跑。

## 教程应显式说明的缺口

- **顶层完成信号会混淆候选与核验成功。** `save_proof()` 每轮覆盖顶层 `proof.md`，而 `pipeline.py` 调回 Stage 1 后以该文件非空设 `ok`，据此打印成功、给 Stage 2 传 `PASS`（[380–386 行](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/decomposition_prover.py#L380-L386)、[820–855 行](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/pipeline.py#L820-L855)）。即使 Stage 1 耗尽而返回空字符串，若最后候选仍在顶层，`ok` 仍为真；这一点由代码直接推出，未做运行复现。检查是否真的被该 harness 接受，应回看相应 proof 目录的报告、verdict 调用轨迹和 `decomposition/STATUS.md`，且其 LLM 接受不等于数学证明。
- **恢复与新输入的一致性未经锁定。** 顶层题目只在缺失时复制，配置则每次覆盖；文件扫描也未比对输入、配置哈希或模型版本（[703–717 行](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/pipeline.py#L703-L717)、[547–625 行](https://github.com/proofQED/QED/blob/121900964e6572aaf094412d434b5ac2a792a65f/code/decomposition_prover.py#L547-L625)）。复用同一输出目录应另核对这些一致性，不能只见 `RESUMING` 就认为条件未变。
- 本笔记是源码静态审计：没有测试异常 CLI、损坏工件、空回应或人工改文件时的全部路径；历史实验的实际中间计划、核验文本、人工介入和耗时须取对应运行日志，不能从此 commit 推定。
