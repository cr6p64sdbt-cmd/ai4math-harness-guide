# Danus `codex` 公开版运行与成稿流程源码定位

核查日期：2026-09-20。唯一代码基准是官方 `frenzymath/Danus` 的 `codex` commit [`6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c`](https://github.com/frenzymath/Danus/tree/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c)。本收据只作静态阅读：没有安装或运行 Danus，没有阅读成果论文的数学证明，也不把运行契约当成执行日志。下列路径均指该 commit；链接中的 `#L` 是原仓库行号。

## 一次项目从输入到 worker 运行

1. **建项目、定问题、分派。** CLI 提供 `new`、`assign`、`finalize`、`start`、`status`、`stop`，其中 `assign` 将某 worker 的 `TASK.md` **替换**，不追加；可用文本、文件或 stdin 输入。`new` 拒绝覆盖已有项目；默认 `--roles high:3,xhigh:4`，即 3 个 high 和 4 个 xhigh worker，名字由解析器生成。共享项目目录含 `global_memory/`、`fact_graph/`、`project.json`，每个 worker 另有 `TASK.md`、私有 `local_memory/`、`.role`、`.status.json`、日志及控制标志。`PROBLEM.md` 的完整问题须由操作/主控侧提供，`do_new` 本身只创建上述框架，不能误写成它会生成数学问题。依据：[CLI 行 1–14、89–101、334–371](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/orchestration/cli.py#L1-L14)、[scaffold 行 116–153](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/execution/scaffold.py#L116-L153)、[layout 行 7–29、216–235](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/execution/layout.py#L7-L29)。
2. **worker 接线与模型。** 脚手架将 worker 契约和技能目录链接到工作目录，写 `.codex/config.toml`，把 MCP gateway 固定为当前 Python 的 `-m danus.gateway`，角色为 `worker`，verify URL 默认 `http://127.0.0.1:8091/verify`，工具超时 3600 秒。每个 worker 的 `.role` 保存模型与 reasoning effort；默认模型来自 `DANUS_WORKER_MODEL`，否则继承 `DANUS_MAIN_MODEL`，内建后备 `gpt-5.6-sol`；默认 effort 由角色 `high` 或 `xhigh` 决定。中性 `DANUS_MAIN_EFFORT=xhigh` 主要供其他 Codex 调用继承，不覆盖脚手架写入的 worker 角色 effort。依据：[scaffold 行 58–109、124–148](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/execution/scaffold.py#L58-L109)、[loop 行 73–83](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/execution/loop.py#L73-L83)、[codex 行 40–41、147–174](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/codex.py#L147-L174)。配置模板只是当前公开版默认值，不能倒填任何历史运行：[config 行 23–49](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/config/danus.env.example#L23-L49)。
3. **启动并行 worker。** `danus start <project>` 遍历项目 worker，按默认 0.2 秒间隔启动；也可只启动 `<project>/<worker>`。每个 worker 外循环是独立进程组；PID 锁和存活检查使重复启动返回 `already-running`/`locked`，启动前清理旧 `.stop`。外循环启动时重写 worker 的 MCP 配置以绑定当前 Python。依据：[CLI 行 166–197](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/orchestration/cli.py#L166-L197)、[scaffold 行 160–175](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/execution/scaffold.py#L160-L175)、[loop 行 185–207](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/execution/loop.py#L185-L207)。
4. **一轮是什么。** 一轮调用一次 `codex exec`，不是一次引理增量。提示词让 worker 读 `TASK.md`、契约、global memory、fact graph、最新 `master_guidance`，从已有状态继续；`-C` 指向 worker 目录，并传 `--dangerously-bypass-approvals-and-sandbox`。输出落在 `logs/round_N.log`；进程退出后写 `.status.json` 的 round、返回码、最后解析到的 fact ID。该 ID 是从日志抓取的状态摘要，不能据此判定目标命题成立。依据：[loop 行 1–10、44–61、130–170、218–241](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/execution/loop.py#L130-L170)。
5. **worker 内部行为来自契约，非 Python 固定算法。** 契约要求每轮先读 `TASK.md` 和 `master_guidance`，查询兄弟 worker 的发现、死路、verification 反馈及可复用事实，再按状态自适应选检索、toy example、反例、分解、直接证明等技能；局部草稿入私有 memory，可共享发现入 global memory，欲作为后续依据的结果经 `fact_submit`。任务空缺或完成时，契约要求在主问题内继续自选方向。Python 外循环只负责再次唤起 Codex，不会检查技能选择、证明质量或是否真读了指导。依据：[worker 契约行 16–33、35–68、70–130、145–149](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/agents/contracts/worker.md#L35-L68)、[loop 行 44–61、130–148](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/execution/loop.py#L44-L61)。`fact_submit` 的内部闸门与图结构由另一份源码收据说明；这里不把 LLM verdict 写成形式证明。

## 主控策略、监控、停止和恢复

- **主控职责是提示词契约。** 当前 [`main_agent.md` 行 1–20](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/agents/contracts/main_agent.md#L1-L20)要求主控进行高层数学推理、维护探索性 subagents、写 `elaboration`/`master_guidance`、分派和监控 worker；subagent 报告仍是未验证线索，须交 worker 承重核验：[行 22–47](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/agents/contracts/main_agent.md#L22-L47)。它还要求持续 Goal、每 30 分钟控制 beat、每 4 小时宏观路线审计：[行 49–92、104–123](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/agents/contracts/main_agent.md#L49-L92)。这些时钟和 Goal 属于主控会话/提示词规范；所读 `danus.execution` 和 CLI 没有实现一个自动唤醒主控的后台 scheduler，不能把 30 分钟审计说成 worker loop 代码保证。当前 contract 与旧文档若写成“main 不做数学”或“两小时复盘”，应标版本/文档漂移。
- **worker 外循环真正的停止条件。** 轮首检查 `.stop`、项目 `.run_deadline`、`DANUS_MAX_ROUNDS`；每轮有 `DANUS_ROUND_HARD_TIMEOUT` 默认 14400 秒，轮间 `DANUS_ROUND_BEAT` 默认 5 秒，连续失败上限默认 5（超时码 124 不计失败）。默认 `DANUS_MAX_ROUNDS=0` 是不限轮。`danus stop` 写 `.stop`，在当前轮结束后生效；`--force` 对进程组发 SIGTERM，最多等待约 5 秒再 SIGKILL。`status` 根据 PID 与状态文件显示 `working`、`stuck?` 等，`stuck?` 是超过硬超时 1.5 倍的软信号。依据：[loop 行 202–255](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/execution/loop.py#L202-L255)、[CLI 行 204–228、283–316](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/orchestration/cli.py#L283-L316)。worker 契约要求目标事实成立或收到停工指令才停：[行 219–224](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/agents/contracts/worker.md#L219-L224)；外循环没有按 fact graph 自动判定“目标已证”并停止的分支，须由主控/操作员控制 `stop`。
- **恢复的是持久状态，不是进程上下文。** 再次 `start` 产生新 Codex 会话，从 `TASK.md`、local/global memory 和 fact graph 重新组织上下文；启动还会重写 MCP 配置。主机重启后，`recover.sh` 调 bootstrap 并重放服务 autostart 清单，但**不**自动恢复 worker loops，需另行 `danus start <project>`。verify 服务要在 worker 提交前可用。依据：[loop 行 44–61、196–207](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/execution/loop.py#L44-L61)、[recover.sh 行 3–46](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/scripts/recover.sh#L3-L46)、[operations 行 79–106](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/docs/operations.md#L79-L106)。静态源码不能证明实际宿主机故障恢复无损。

## 已有结果如何变成人类报告或论文

- **确定成稿目标。** `danus finalize <project> [--paper id] <fact_id>...` 只接受图内已有 ID，去重后写目标 `TARGET.md`；不带 ID 时仅列出图中的 terminal fact 候选，不替操作员选择。default paper 使用 `<project>/TARGET.md`、`<project>/paper/`，其他 `paper_id` 使用 `<project>/papers/<paper_id>/`。`paper_write` 的目标优先级是显式 `headline`、brief 的 `headline_fact_ids`、再到 `TARGET.md`；全空返回 `needs_target`，不写 `main.tex`。依据：[CLI 行 108–159](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/orchestration/cli.py#L108-L159)、[assemble 行 212–277](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/write_paper/assemble.py#L212-L277)、[paper server 行 632–647、673–696](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/write_paper/server.py#L673-L696)。这里的“已入图”是系统内部状态，不是人类已接受数学定理。
- **论文路径。** 主控先准备 `PROJECT_BRIEF.md`，从目标的前驱闭包汇总 `external_refs` 到 `REFERENCE_LEDGER.md`；`paper_subgraph` 给主控仅含 statement 和 DAG 关系的紧凑骨架，再由主控挑承重事实传给 `paper_write(fact_ids=..., instructions=...)`。单次 writer 读取选中事实的完整证明及其他必要前驱的 statement，生成 `main.tex`；若不选 `fact_ids`，走整闭包路径，大图有上下文膨胀风险。超过 `DANUS_PAPER_WRITE_CHUNK_CHARS` 时会自动 planner→分节 writer→拼接；失败不写成稿。`paper_write` 默认 `stop_workers=False`，显式 true 才请求温和停 swarm；函数签名和执行分支优先于相邻旧注释中“default stop”的说法。依据：[write-paper skill 行 199–260、297–375、421–441](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/.agents/skills/write-paper/SKILL.md#L297-L375)、[paper server 行 605–662、697–808、811–833](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/write_paper/server.py#L605-L662)。
- **成稿后各关口分立。** writer 成功只说明非空 Codex 输出经泄漏检查并落盘；首次编译要运行 `compile_verify.sh`。随后 reference auditor 离线列疑点，reference verifier 联网核对，reviser 按结果修正并内部编译重试，最后 `paper_verify_math` 对**论文正文**进行一次新的整体 LLM 复核。后者的失败运行是 `verify_error`，不能当通过；这些是 Danus 的文稿流程，不是 formal kernel。依据：[write-paper skill 行 569–659、660–709、711–748](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/.agents/skills/write-paper/SKILL.md#L711-L748)、[paper server 行 1647–1682](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/write_paper/server.py#L1647-L1682)。可选 `paper_id` 允许同一事实图下多篇文稿，不能据此假设多篇稿件各自数学已由人独立认可。
- **报告是另一入口。** `summary_write` 将 `PROBLEM.md` 原文和当前**所有**图内事实的 statement/proof/intuition（按依赖顺序、去掉内部 ID/元数据）嵌入一次性 writer prompt，生成 `<project>/report/report.md`；泄漏检查未过会隔离为 `report.leaky.md`。它不是论文目标闭包过滤，也不会自动补入未核验的 global memory 路线。依据：[summary assemble 行 107–180](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/human_summary/assemble.py#L107-L180)、[summary server 行 115–170](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/human_summary/server.py#L115-L170)。这与报告 prompt 期待覆盖 active/parked 等路线之间存在信息接口张力：若某路线只有未入图的 memory 记录，隔离 writer 并未获得它；不能承诺完整路线组合报告。
- **隔离写作的准确边界。** paper/report/auditor 默认以空临时 cwd、完全嵌入的 prompt、`codex exec --sandbox read-only` 运行，stdout 作为文稿；reference verifier 是例外，开启 web 与 gateway 只读检索并使用高权限 flag。源码自己指出 read-only sandbox 主要限制写入，空 cwd 不等于系统级文件读取隔离；这些是代码设定，不是我们试运行的安全验收。依据：[authoring driver 行 1–29、83–142](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/authoring/driver.py#L83-L142)。

## 可直接用于教程的证据边界

这份定位支持解释**公开源码安排的控制流**，不支持声称某个历史数学项目按这些默认值实际运行，或其数学结论正确。worker 的自适应换路、主控的定时战略审计、目标完成后的停工、论文的人工编辑质量分别依赖提示词遵循和人的选择；静态源码只验证了 CLI、持久文件、外循环与写作工具的接口。另一个值得读者亲自检查的细节是 `paper_write` 默认不停止 worker，而写作技能要求主控在写稿前就此作操作决策；两个层次相容，但不可简写为“开始成稿即自动停工”。
