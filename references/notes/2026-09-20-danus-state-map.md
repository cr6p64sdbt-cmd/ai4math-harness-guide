# Danus 事实状态与 verifier 接口定位（2026-09-20）

本笔记只读官方 `frenzymath/Danus` 的 `codex` 固定 commit [`6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c`](https://github.com/frenzymath/Danus/tree/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c) 中的源码与 agent contract。定位方式为按固定 SHA 请求 GitHub 官方 raw 文件，并按原始文件逐行编号；未下载、安装或运行 Danus，也未测试 MCP/HTTP 服务。下文“实现”仅指此版本源码的静态路径，不等于历史 YTD 运行快照，更不等于数学正确性验收。

## 一条候选事实的路径

1. Worker 可以调用 `gm_add` 发布共享 finding，也可以用 `gm_search` 与 `fact_search` 检索已有内容；main 可以调用前两者和 `fact_search`，但没有 `fact_submit`；verifier 的 MCP 工具集只有 `search_arxiv_theorems`。未识别角色回退到 verifier 工具集，显式 `all` 才暴露所有工具。[`roles.py` 23–45](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/gateway/roles.py#L23-L45)；[`server.py` 297–303](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/gateway/server.py#L297-L303)。这是 **MCP 工具暴露表**；不能由此推论进程文件系统权限受同等隔离。
2. `fact_submit(statement, proof, predecessors, glossary_introduces, intuition, source_id, external_refs)` 先检查未定义符号，但异常被吞掉，检查结果只是附带提示；随后向本地 verify URL 发送 `{statement, proof}`，服务不可用则返回 `verdict: error`，不入图。[`server.py` 150–204](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/gateway/server.py#L150-L204)。`predecessors`、`source_id` 等并未进入这次 HTTP 请求，verifier 必须依 agent contract 自行读取所需上下文；代码层面没有把依赖文件打包送审。
3. `/verify` 首先执行空洞陈述/证明和 P1/P3/P5 文本预检，拒绝时给 HTTP 400；通过才启动新的 Codex verifier。[`service.py` 43–50](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/verify/service.py#L43-L50)；[`prechecks.py` 183–208](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/verify/prechecks.py#L183-L208)。每次运行分配独立目录；launcher 以新 `codex exec` 进程启动 verifier，读取其 `verification.json` 并返回 JSON；超时、非零退出、缺文件或无效 JSON 转为 HTTP 错误。[`launcher.py` 112–130, 156–213](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/verify/launcher.py#L112-L213)。launcher 注入 `DANUS_ROLE="verifier"`，同时给该 Codex 进程传入 `--dangerously-bypass-approvals-and-sandbox`；因此“verifier 只读”是 gateway 工具表与提示契约的声明，**不是** OS 沙箱隔离结论。[`launcher.py` 97–101, 156–166](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/verify/launcher.py#L97-L166)。
4. Verifier contract 要求按正文顺序检查推理、假设和外部引用，`critical_errors` 与 `gaps` 都为空才写 `verdict="correct"`，否则写 `wrong` 与修复建议；它明确禁止运行数值/符号计算或 proof assistant，并允许读取事实图作上下文。[`verifier.md` 25–50, 121–152](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/agents/contracts/verifier.md#L25-L152)。这是**冷启动 LLM 文本审阅**，不是形式内核证明；`service.py` 也明确如此界定。[`service.py` 6–10](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/verify/service.py#L6-L10)。
5. Gateway 只在 `result.get("verdict") == "correct"` 时调用 `FactGraph.add`。无论 `correct`、`wrong` 或 `correct` 但事实写入失败，代码随后尝试向 global memory 写 `verification` 记录；`wrong` 返回修复建议，写入失败则可能返回 `{accepted: true, fact_id: null, write_error}`。[`server.py` 203–246](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/gateway/server.py#L203-L246)。因此教程中应以 **`fact_id` 非空** 区分“事实已经入图”；单看 `accepted: true` 不够。`gm.append` 本身没有被这里的 `try` 包住，事实写与日志写也无事务；代码不能绝对保证任何 I/O 故障下仍留下 trace。

## 三层状态和依赖撤销

- **Local memory** 位于单个 worker 目录的 `local_memory/*.jsonl`，默认 `notes`、`events`；`append` 将非事件记录另记一条 breadcrumb，`search` 用 BM25 检索。它记录粗略过程，不是共享数学事实。[`local_memory.py` 1–5, 20–69](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/core/local_memory.py#L1-L69)。接口设计让 agent 直接读写这些文件，不提供 local-memory MCP 工具；`LocalMemory` 类是底层数据结构。[`INTERFACES.md` 35–48, 115–118](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/core/INTERFACES.md#L35-L118)。
- **Global memory** 是项目共享、按 kind 分开的 JSONL finding。`conclusion`、`example`、`counterexample`、`proof_attempt` 默认 `verifiable=True` 且写入时须有非空 evidence；计划、障碍、死路、指导、verification 等属于不同 kind。entry 初始状态是 `unverified` 或 `open`；`set_status` 只在 `_status.jsonl` 追加转换，读取时折叠最新记录。状态生命周期由 agent 操作，存储类没有证明状态的自动提升机制。[`schema.py` 25–45](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/core/schema.py#L25-L45)；[`global_memory.py` 35–109](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/core/global_memory.py#L35-L109)。`gm_add`/`gm_search` 由 gateway 包装。[`server.py` 115–143](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/gateway/server.py#L115-L143)。
- **Fact graph** 的每个现行节点是 `fact_graph/facts/<fact_id>.md`，含陈述、证明、前驱 ID、术语定义与外部文献元数据。ID 是对 `problem_id`、排序后的 `predecessors`、术语、规范化陈述与证明取 SHA-256 前 16 个十六进制字符；`external_refs` 是可变元数据，不入哈希。[`factgraph.py` 47–70, 110–166](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/core/factgraph.py#L47-L166)；[`schema.py` 104–130](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/core/schema.py#L104-L130)。`fact_search` 每次从现行事实文件生成 BM25 搜索视图，而不是维护另一个持久 board；搜索命中供 agent 读全文判断。[`factgraph.py` 199–220](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/core/factgraph.py#L199-L220)。
- `fact_revoke` 在 main 的 MCP 工具表中；实现先从各现行节点的 `predecessors` 递归查找后代，再将目标与后代移入 `_revoked/`，逐个追加 `revocation_log.jsonl`。之后的 `add` 会拒绝显式引用已撤销 ID 的新事实。[`server.py` 260–265](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/gateway/server.py#L260-L265)；[`factgraph.py` 254–268, 295–316](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/core/factgraph.py#L254-L316)；[`factgraph.py` 144–149](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/core/factgraph.py#L144-L149)。这是**显式前驱边**上的撤销；源码中 `add` 未检查前驱 ID 是否确实存在，未从证明正文自动抽取所有引用边，也未自动更新 global-memory finding 的状态或重审稿件。完整依赖性因此仍取决于 worker 正确填写 `predecessors`。

## 教程应保留的实现边界

此固定版用代码实现“工具可见性 → 候选事实提交 → 预检与 LLM 判读 → `correct` 才写事实 → 共享反馈 → 显式依赖撤销”的主线，但没有由源码证明事实图中的数学命题是真的。`FactGraph.add` 是可由 Python 直接调用的存储方法，所谓“唯一事实写入路径”是 gateway/工作流约定而非文件系统强制访问控制。[`factgraph.py` 124–166](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/core/factgraph.py#L124-L166)。Verifier 的 `verification.json` 在 launcher 中只检查是 JSON object；`verdict`/report 的形状与相互一致性主要靠 agent contract，gateway 对 `verdict` 只做字符串等值判断。[`launcher.py` 200–213](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/verify/launcher.py#L200-L213)；[`server.py` 203–204](https://github.com/frenzymath/Danus/blob/6d92e8d415933ca2ef52fd1a4da73fdfcd418f1c/danus/gateway/server.py#L203-L204)。

这次阅读未检查实际部署文件权限、并发写入竞争、完整失败恢复脚本或历史案例的运行工件；静态代码说明可用接口及其明显限制，不能断言在用户机器或历史案例中已经实测成立。
