# OpenAI 十项结果：Astra 生成、成稿与形式化工作流审计

## 分层判断

- **数学状态**：`OPEN`。这是十个不同领域的结果包，本项目尚未逐项完成 statement lock、assumption audit 和 paper-to-Lean semantic audit。
- **AI 贡献**：OpenAI 明确声称数学论证由内部 Astra 生成；这是强 attribution claim，但缺少原始运行记录支持独立过程审计。
- **形式验证**：公开 Lean certificates 与 Comparator 入口使输出比普通预印本更可检查；它们不自动验证线性论文的每个推理，也不自动证明形式 statement 等于宣传命题。
- **复现**：`OUTPUT-CHECKABLE / DISCOVERY-NOT-REPRODUCIBLE`。模型、prompt 和搜索协议未公开。
- **纠错信号**：第六章一条 lemma 的打印证明出现 polarity error，已有局部修复；这不等于主定理被推翻，也不等于主定理已获独立验证。

## 准确的数学目标

官方页面把十项结果归入：

1. high-dimensional sphere packing；
2. asymptotically good codes；
3. nonsofic groups；
4. Connes rigidity；
5. arithmetic circuits；
6. quantum parallel repetition；
7. closest vector problem；
8. Ehrhart volume conjecture；
9. multicolor Ramsey numbers；
10. extremal graph theory 中的 compactness 与 degeneracy conjectures。

本 dossier 审计的是这批结果的生成与验证机制，不尝试在一份文件里裁决十个专业领域的全部数学证明。每项若进入后续深读，应拆成独立 theorem/claim card，锁定论文版本、formal statement、定义、依赖和领域专家反馈。

## 研究时间线

1. OpenAI 在内部评估期间把一组开放问题交给 Astra；公开材料没有说明选择机制与每题初始 prompt。
2. 官方称 Astra 生成十项数学论证；总 token 量按 Sol API rate 估算约 2,000 美元。
3. 人类团队用同一模型把论证整理为 manuscripts，并帮助完成形式化。
4. 模型为每项结果生成 Lean certificate；项目发布独立 challenge/solution 结构与 Comparator 检查入口。
5. 另一个模型把探索过程重构为 readable reasoning walkthroughs；这些不是原始 chain-of-thought logs。
6. 组合论文于 2026-08-01 发布；本次检查到的版本标注 2026-08-06 更新。
7. 2026-08-03 提交的独立纠错指出第六章一条 greedy conditioning lemma 的打印证明含 success/failure polarity reversal，并给出局部修复。

## 系统配置

- generator：internal version of Astra；准确 checkpoint 与 inference parameters 未公开；
- workload：十个开放问题；每题 token、wall time 和并行度未公开；
- cost signal：官方称总 token 若按 Sol API rates 计约 2,000 美元，不包括人工、硬件和失败路线成本；
- manuscript stage：humans + same model；详细 edit history 未公开；
- formalization stage：模型生成 Lean certificates，人类帮助形式化；
- Lean artifact：Lean 4.32.0/Mathlib project，提供 `lake exe cache get`、`lake build All` 和 Comparator-compatible checks；
- narration：model-generated reconstruction；不是原始运行 transcript；
- external validation：发现一项公开局部纠错；未找到十项全部的独立逐项验证。

## AI完成的工作

来源明确支持：

- 生成十项结果的 mathematical arguments；
- 在 manuscript preparation 中协助人类；
- 为每项 argument 生成 Lean certificate；
- 生成面向读者的 reasoning narration。

来源没有公开足够数据来区分：Astra 是提出关键 construction、关键 lemma、完整 proof route，还是在某些题上从人类选择的候选继续完成。组合式 attribution 不应替代逐题贡献记录。

## 人的参与

- 选择并发布结果集合；
- 与同一模型把论证整理成 manuscripts；
- 帮助 formalize proofs；
- 承担正确性与对数学共同体的责任；
- 决定公开 paper、Lean artifacts 与 reconstructed walkthroughs。

问题选择、prompt 修订、错误修复和逐题数学编辑量为 `UNKNOWN`。不能因官方使用“arguments generated by our system”就把所有人类数学判断记为零。

## 研究机制重建

```text
human-selected open problem set
        ↓
private Astra research inference
        ↓
candidate mathematical argument per problem
        ↓
human + model manuscript preparation
        ├─ definitions and exposition
        ├─ references and contextualization
        └─ corrections/editing
        ↓
model-assisted Lean formalization
        ↓
kernel-checkable certificate + trusted challenge statement
        ↓
Comparator / build interface
        ↓
separate model reconstructs readable walkthrough
        ↓
public release → external mathematical criticism/correction
```

可学习的核心是“发现工件、论文工件、形式工件、叙述工件分开发布”。当前最大机制缺口也在这里：没有公开连接这些工件的 provenance map，无法逐步回答某个 informal argument 如何变成 theorem statement 和 proof term。

## 复现条件核查

### 可公开检查的材料

- 组合论文和章节级主张；
- 十项 Lean projects 与总构建入口；
- Comparator-compatible challenge/solution separation；
- reasoning walkthroughs；
- 至少一份外部纠错说明。

### 重做发现过程仍缺少的材料

- Astra checkpoint/API；
- original prompts、system instructions 和 problem packaging；
- 搜索树、失败路线、工具调用和停止条件；
- 每题 token、runtime、worker topology 与人工交互；
- manuscript 与 formalization 的 edit/provenance logs。

因此不能写“照此使用 Astra 即可复现十项结果”。目前只能复核公开输出。

## 数学证据核查

应对每项结果分别进行五层检查：

1. 锁定 paper 的准确 theorem statement；
2. 锁定 Comparator trusted statement 及 definitions；
3. 核对 informal 与 formal statement 语义等价；
4. 运行 Lean build、axiom audit 和 Comparator；
5. 由领域专家检查引用、意义、novelty 与 manuscript explanation。

公开纠错只直接影响第六章打印证明的一条 lemma proof。纠错论文称 statement 正确、repair local、后续参数不变，同时明确没有独立验证 main theorem。本项目保留这三个限定，不升级也不夸大为整项失败。

## 可学习的方法

1. 重大 AI 数学发布应提供 statement、solution、proof term 和 build command，而不仅是 PDF；
2. 形式验证不能替代 informal-to-formal semantic audit；
3. reasoning reconstruction 有解释价值，但必须与原始 trace 明确区分；
4. 组合发布需要 per-result 状态表，否则一个纠错会被误解为整包通过或整包失败；
5. manuscript checker 应作为 formalization 之外的独立关口。

目前不能判断 Astra、更多 test-time compute、问题选择还是形式化反馈中的哪一项导致成功；没有公开消融。
